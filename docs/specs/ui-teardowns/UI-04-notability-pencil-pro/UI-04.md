### P4 · Barrel-roll chisel nib (backlog)
- Nib angle: $\theta_{nib} = \rho + \alpha + \theta_{offset}$
  - $\rho$ = roll (`UITouch.rollAngle`, iOS 17.5, checked in SDK)
  - $\alpha$ = azimuth; $\theta_{offset}$ = nib's set angle.
- Width: $W = f \cdot \sqrt{(W_{max}\cos(\phi-\theta_{nib}))^2 + (W_{min}\sin(\phi-\theta_{nib}))^2}$
  - $\phi$ = stroke direction; $f$ = pressure factor.
  - Convention: $\phi = \theta_{nib}$ → $W = f \cdot W_{max}$.
- Assumption: adding roll and azimuth is exact only for an upright pencil.
- Roll reaches the web view only through a native bridge
  (web pointer events lack roll — from memory, verify).

### P5 · Finger and trackpad write like the Pencil (owner 2026-11-16)
- One pointer pipeline: Pointer Events from pen, touch and trackpad feed one stroke engine, `editor/src/ink.js`.
- Pencil pressure passes through. Finger and trackpad report a flat pressure, so it is synthesized from speed:
  $p = \mathrm{clamp}(p_{slow} + (p_{fast}-p_{slow})\cdot\frac{v-v_{slow}}{v_{fast}-v_{slow}})$, then smoothed $p \leftarrow p + 0.35\,(p_{target}-p)$.
- Defaults (a guess, tunable in `editor/src/pressure.js`): $p_{slow}=0.75$, $p_{fast}=0.3$, $v_{slow}=0.2$, $v_{fast}=2.5$ px/ms.
- Built `[x]` 2026-11-16: `pressure.js`, wired in `ink.js` onPointerDown/Move; test `ui04-p5-pressure.test.mjs`.
- Next: eraser and undo parity (two-finger tap), then P1-P4. Device check owed on iPad, iPhone, Mac trackpad.

### P6 · Palm rejection for finger and trackpad (owner 2026-11-16)
Owner: "there should be a palm rejection equivalent but for ergonomic cases of using a trackpad pointer
(drawing from mac) and finger for touchscreen without pencil (iphone, ipad without pencil) -- all should
feel the same as using a pencil".
- Code: `editor/src/palm.js` (pure gate, per-pointer state), wired in `editor/src/ink.js` pointer handlers.
- Numbers are DEFAULTS (assumed, not yet measured on the owner's devices); tune in `palm.js`.
- Per touch state: `wait` → `ink` | `ignore` | `scroll` | `pan`. Mouse and pen go straight to ink.
- **Two fingers scroll.** A second touch landing while the first is `wait`, or `ink` for under
  `TWO_FINGER_MS = 250` ms, turns both into `scroll`: the live stroke is dropped, and the scroller moves by
  the pair's centroid delta (`scrollTop -= dy`, `scrollLeft -= dx`). A second touch after that is ignored
  (a palm landing mid-stroke). Touches already `ignore` don't count toward two. Closes BUG-21's open item.
  No pinch: the editor has no zoom today.
- **Palm size.** A touch whose `width` or `height` exceeds `PALM_CONTACT_PX = 50` CSS px is `ignore`;
  a `wait` touch that grows past it becomes `ignore`.
- **Resting contact.** A touch starts ink only after moving `TOUCH_SLOP_PX = 4` px within `REST_MS = 300` ms
  of landing; otherwise it is `ignore` until lifted (resting palm or thumb). The buffered points are kept,
  so the stroke starts where the finger landed.
- **Tiny strokes.** Touch and mouse strokes whose points all lie within `MIN_STROKE_PX = 3` px of the first
  are dropped (same size as `AUTO_PEN_TAP_PX`). Trade-off: a finger or trackpad i-dot needs a small flick.
- **Trackpad brush.** A mouse stroke shorter than `BRUSH_MS = 60` ms with extent under `BRUSH_PX = 8` px is
  dropped (tap-to-click brushed while moving). Width from speed stays P5.
- **System edge.** A touch starting within `EDGE_BOTTOM_PX = 34` px of the viewport bottom (home indicator)
  is `ignore` (left to iOS). No side bands (changed 2026-11-16): Draftpad's web view enables no back-swipe
  (no `allowsBackForwardNavigationGestures` in `mobile/HostApp/iOS/`), so the side edges are page margin a
  finger must be able to write in (BUG-06's drag starts at x = 10).
- **Pencil in use.** While a pen pointer is down, touches are `ignore`; a touch inking when the pen lands is
  dropped. Within `PEN_GRACE_MS = 30000` ms of the last pen event, one finger `pan`s (scrolls) instead of
  inking, as Notability does in Pencil-only mode.
- **Trackpad page drift.** While a tool other than Select is chosen, a capture `mousedown` on the scroller is
  stopped, so CodeMirror never starts a text-selection drag (which autoscrolls the page under the pointer).
- Built `[~]` 2026-11-16: `palm.js`, wired in `ink.js`; test `ui04-p6-palm.test.mjs`. Device check owed on iPhone, iPad, Mac trackpad.

#### P7 · Hold-to-snap polygons with corner handles (gap 1)
- Same gesture as today: hold still `SNAP_HOLD_MS = 500` ms at the end of a stroke bigger than `SNAP_MIN_SIZE = 40` px.
- A closed loop (ends within `max(8, 0.15·size)`) is simplified to corners (Douglas–Peucker, tolerance 7 % of size).
  3 corners → triangle (one angle within 12° of 90° → right triangle); 4 → rectangle (all angles within 15° of 90°),
  trapezoid (one pair of sides within 12° of parallel), else a free quadrilateral; 5 → pentagon (regular if its corners
  sit within 25 % of their mean radius). 6+ corners, or an ellipse that fits better, → ellipse (unchanged).
- Tidying: sides within 8° of horizontal/vertical are made exactly so; an isosceles trapezoid (legs within 20 %) is
  made symmetric; a regular pentagon is made regular.
- Invariants: a held near-straight stroke is still a `line`; a held round loop is still an `ellipse`; letter-sized
  or un-held strokes never snap; the Circle/Underline tools are unchanged.
- **Corner handles:** right after a polygon or line snap, blue dots sit on its corners (line: ends). Dragging a dot moves
  that corner (pen, finger or trackpad). They go when the next stroke starts or the tool changes.
- Done: unit tests for triangle, right triangle, rectangle, trapezoid, pentagon, circle-stays-ellipse,
  line-stays-line, letter-stays-ink, unheld-stays-ink; device check on iPad (Pencil), iPhone (finger), Mac (trackpad).

- Built `[~]` 2026-11-16: `inkshapes.js` `fitPolygon`, `polygonPoints`, `shapeHandles`, `moveHandle`; `ink.js` `detectAndSnapShape`
  (polygon before ellipse), handles in `drawHandles`/`handleAt`. Device check owed.
