# UI-06 · Draftpad page navigation, gesture-only (Antinote study)

From: owner 2026-11-15 ("deconstruct antinote.app, fix navigation controls of draftpad"; corrections same day),
T-0020/T-0021/T-0022/T-0024 (top bar notes, 2026-11-12) · Embodiments: Mac, iPhone, iPad (shared `editor/`)

## Study: Antinote (bundle strings of `/Applications/Antinote.app`; clean-room, model only)
- One stack, newest at the front. Horizontal trackpad swipe moves older/newer; swipe sensitivity is a setting.
- Actions: go to latest, promote a note to the front, new note at the front, delete.
- Top-bar buttons appear only while the pointer is over the top edge.
- Slotted notes: nine fixed notes reached directly, shown in their own bar; they are never promoted or deleted.
- Antinote binds every action to a ⌘ key. **Draftpad binds none** (owner): gestures plus visible controls.

## Layout (unchanged)
Page 0 = newest, on the left. Older pages to the right.

## Gestures (one rule for trackpad, touch, Pencil, mouse; BUG-02 slop 12 px, ratio 1.4)
- G1 · Swipe right-to-left: one page older. On an empty page (BUG-18 A1): that page is deleted instead.
- G2 · Swipe left-to-right: one page newer. On page 0 with text: a new empty page opens at the front.
- G3 · Tap a page dot: go to that page.
- G4 · Drag a page dot and release it left of the first dot: that page moves to the front (promote).
  Only the order changes; the page's text is byte-identical.
- G5 · Hold a page dot 500 ms (moving < 8 px): a sheet opens: Promote to front · Slot 1–9 · Clear slot.
- G6 · Tap a slot dot: go to the page in that slot.

## Visible controls (law: every gesture has a control, a menu item and a voice phrase)
- Top bar, faded until the pointer or a touch is in the top 48 px: `＋` new page · `‹` newer · page dots · `›` older · slot dots.
- `···` menu: New page, Newer page, Older page, Promote to front. No shortcut hints.
- Voice (`gestures.js`): "new page", "newer page", "older page", "promote", "slot 1" … "slot 9".
- Every control, gesture and voice phrase calls the same function in `pagemode.js`.

## Keys
- K1 · No page-navigation keys: ⌘[ and ⌘] are not bound.

## Slots
- S1 · A slot is a hidden line on the page: `<!-- slot N -->` (N = 1–9), next to `<!-- saved … -->`.
  Plain markdown, invisible in Obsidian, carried by the existing sync; it moves with the page when promoted.
- S2 · One page per slot: setting slot N on a page clears N from any other page.
- S3 · A slotted page is never empty (its slot line is text), so swipe never deletes it.

## Reopen
- R1 · Draftpad opens on the page you were last on, per device (stored locally: page index + its first line).
  If that first line is found on another page (pages added elsewhere), that page wins; else the index, clamped.

## Thresholds
- Hold: 500 ms. Tap: < 8 px movement and < 500 ms. Dots: ≥ 28 px hit target on touch (44 pt row).

## Bar stays put (found while checking in WebKit, 2026-11-15)
- B1 · Lifting a finger on the bar does not fade it (the haptic zone's pointerup did, so the next tap on touch
  hit the page behind: T-0024 "top strip fails mobile").
- B2 · Page actions from the bar (new, delete, promote, slot) do not fade it; only writing does.
- B3 · While the hold sheet is open the bar stays visible and its buttons take the tap.
- Not reachable by `npm test` (mock DOM has no event propagation): checked in the browser pane against `dist/editor.html`.
