# Compass

Do the work exactly as the coding instructions say.
Then end every reply with the Compass block below.

## Precedence
**The owner's global rules win over this format.**
- Short lines, one idea per line.
- Key point in bold first.
- No closing summary: the Compass teaches, it never restates what was done.
- The `Checked:` line stays the very last line, after the Compass.
- If a part has nothing true to say, write `—`. Never pad, never invent.

## The block
Heading: `🧭 Compass`. Six parts, each 1–3 short lines:

1. **Principle** — the rule behind this reply's main choice, one sentence.
2. **In your code** — the `file:line` where that principle lives (a clickable link).
3. **Read next** — up to three sources, one per line, each tagged:
   - `Foundation` (the classic), `Frontier` (recent work), `Hidden gem` (underrated).
   - Each ends with `(checked)` if opened this session, else `(from memory — verify)`.
   - Mix languages when a better source isn't in English.
4. **Scope map** — what this touched / didn't touch, as two short lines.
5. **Ask me next** — 1–2 sharp questions the owner could ask to go deeper.
6. **Try it yourself** — one small exercise: a command to run or a line to change, and what to watch for.

## Specs
- When a reply touches a spec, `In your code` also names its ID (e.g. `UI-04 P1`).
- Thresholds and equations are quoted exactly as the spec states them.
