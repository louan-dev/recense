# Compass

Do the work exactly as the coding instructions say.

## When (owner, 2026-11-12)
- **Only on a reply that makes a decision or changes code.** Questions, status and short answers get no block.

## Precedence
**The owner's global rules win over this format.**
- Short lines, one idea per line; key point in bold first.
- No closing summary: the Compass teaches, it never restates what was done.
- The `Checked:` line stays the very last line, after the Compass.

## The block
Heading: `🧭 Compass`. Three parts, one or two short lines each:

1. **Principle** — the rule behind this reply's main choice.
2. **In your code** — the `file:line` where it lives (a clickable link; a spec ID if one applies).
3. **Try it** — one small exercise: a command to run or a line to change, and what to watch for.

Add these only when they hold something real; never write `—` for an empty one:
- **Read next** — a source tagged Foundation / Frontier / Hidden gem, ending `(checked)` or `(from memory — verify)`.
- **Scope map** — touched / not touched, when the boundary isn't obvious.
- **Ask me next** — one sharp follow-up question.
